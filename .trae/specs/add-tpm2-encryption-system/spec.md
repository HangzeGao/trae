# 基于 TPM 2.0 的软硬结合加解密系统 Spec

## 技术选型
- **开发语言**: Go
- **TPM 库**: github.com/google/go-tpm (Google 维护，TPM 2.0 完整支持)
- **API 形式**: REST API (HTTP/HTTPS)，基于 Go 标准库 net/http
- **加解密算法**: AES (128/192/256) + SM4 (128)，支持 GCM/CBC/CTR/CFB/OFB 分组模式
- **密钥封装**: TPM 内部 RSA/ECC (根密钥加密数据密钥)
- **数据密钥存储**: 仅存储加密后的密文，持久化到本地文件或数据库
- **部署模式**: 单机隔离部署、多虚机/集群部署（集中式密钥服务 + 分布式加解密节点）

## Why
当前系统缺乏基于硬件安全模块的加解密能力，数据密钥以明文形式存储在内存或磁盘中，存在泄露风险。利用 TPM 2.0 芯片的硬件安全特性，可以实现根密钥永不离开芯片、数据密钥受根密钥保护的两层密钥体系，显著提升密钥安全性。

## What Changes
- 新增 TPM 2.0 根密钥（Root Key）管理模块：在 TPM 芯片内创建/加载根密钥，根密钥私钥部分永不离开 TPM
- 新增数据密钥（Data Key）管理模块：生成随机数据密钥，使用根密钥加密后持久化存储，使用时由 TPM 解密到内存
- 新增多算法多模式数据加解密模块：支持 AES (128/192/256) 和 SM4 (128) 的 GCM/CBC/CTR/CFB/OFB 分组模式
- 新增统一的加解密 REST API，对外提供密钥管理和加解密能力
- 新增集群部署支持：密钥服务节点（连接 TPM）与加解密工作节点可分离部署
- **BREAKING** 无，此为全新功能

## Impact
- Affected specs: 无已有规格受影响
- Affected code: 全新模块，不影响已有代码

## ADDED Requirements

### Requirement: TPM 2.0 根密钥管理
系统 SHALL 在 TPM 2.0 芯片内创建和管理根密钥（Storage Root Key），根密钥的私钥部分永不离开 TPM 芯片。

#### Scenario: 首次初始化根密钥
- **WHEN** 系统首次启动且 TPM 中不存在根密钥
- **THEN** 系统在 TPM 中创建新的根密钥（SRK），并返回根密钥句柄

#### Scenario: 加载已有根密钥
- **WHEN** 系统启动且 TPM 中已存在根密钥
- **THEN** 系统加载已有根密钥并返回句柄，不重复创建

#### Scenario: TPM 不可用
- **WHEN** TPM 设备不可用或驱动异常
- **THEN** 系统返回明确的错误信息，拒绝继续操作

### Requirement: 数据密钥管理
系统 SHALL 支持数据密钥的生成、加密存储和解密加载，数据密钥由根密钥加密保护。

#### Scenario: 生成数据密钥
- **WHEN** 用户请求生成新的数据密钥
- **THEN** 系统生成 256 位随机数据密钥，使用根密钥在 TPM 内加密数据密钥，返回加密后的数据密钥密文和明文数据密钥（仅本次返回）

#### Scenario: 解密数据密钥
- **WHEN** 用户需要使用已加密的数据密钥
- **THEN** 系统将加密的数据密钥密文送入 TPM，由根密钥解密，返回明文数据密钥供加解密使用

#### Scenario: 持久化数据密钥
- **WHEN** 用户需要保存数据密钥
- **THEN** 系统仅存储加密后的数据密钥密文，不存储明文数据密钥

### Requirement: 数据加解密
系统 SHALL 使用数据密钥对业务数据进行加解密操作，支持多种算法和分组模式。

支持的算法与模式：
- AES: 128/192/256 位密钥，GCM/CBC/CTR/CFB/OFB 模式
- SM4: 128 位密钥，GCM/CBC/CTR/CFB/OFB 模式

#### Scenario: 加密数据（指定算法和模式）
- **WHEN** 用户传入明文数据、加密后的数据密钥密文、算法（如 AES-256）和模式（如 GCM）
- **THEN** 系统先通过 TPM 解密数据密钥，再使用指定算法和模式加密数据，返回密文（GCM 模式包含认证标签）

#### Scenario: 解密数据（指定算法和模式）
- **WHEN** 用户传入密文、加密后的数据密钥密文、算法和模式
- **THEN** 系统先通过 TPM 解密数据密钥，再使用指定算法和模式解密数据，返回明文（GCM 模式验证认证标签）

#### Scenario: 不支持的算法或模式
- **WHEN** 用户指定不支持的算法或模式
- **THEN** 系统返回错误信息，拒绝操作

#### Scenario: 数据密钥长度与算法不匹配
- **WHEN** 数据密钥长度与指定算法不匹配（如 128 位密钥用于 AES-256）
- **THEN** 系统返回错误信息，拒绝操作

#### Scenario: 数据密钥解密失败
- **WHEN** 数据密钥密文被篡改或与根密钥不匹配
- **THEN** TPM 解密失败，系统返回错误信息，拒绝加解密操作

### Requirement: 统一加解密 REST API
系统 SHALL 提供 REST API 接口，封装密钥管理和加解密操作，供用户通过 HTTP 调用。

#### Scenario: 初始化服务
- **WHEN** 应用启动并初始化服务
- **THEN** 服务自动连接 TPM、加载/创建根密钥，启动 HTTP 服务进入就绪状态

#### Scenario: 生成数据密钥
- **WHEN** 用户调用 POST /api/v1/keys/generate，指定算法（如 AES-256 或 SM4）
- **THEN** 系统生成对应长度的数据密钥，使用根密钥加密，返回加密后的数据密钥密文和明文数据密钥

#### Scenario: 加密数据
- **WHEN** 用户调用 POST /api/v1/encrypt，传入明文、加密后的数据密钥密文、算法和模式
- **THEN** 系统通过 TPM 解密数据密钥 + 指定算法模式加密，返回密文

#### Scenario: 解密数据
- **WHEN** 用户调用 POST /api/v1/decrypt，传入密文、加密后的数据密钥密文、算法和模式
- **THEN** 系统通过 TPM 解密数据密钥 + 指定算法模式解密，返回明文

#### Scenario: 轮换数据密钥
- **WHEN** 用户调用 POST /api/v1/keys/rotate，传入旧数据密钥密文和算法
- **THEN** 系统生成新数据密钥，使用根密钥加密后返回新密钥密文

#### Scenario: 查询支持的算法和模式
- **WHEN** 用户调用 GET /api/v1/algorithms
- **THEN** 系统返回支持的算法列表及各算法支持的模式列表

### Requirement: 密钥生命周期管理
系统 SHALL 支持数据密钥的轮换和废弃。

#### Scenario: 轮换数据密钥
- **WHEN** 用户请求轮换数据密钥
- **THEN** 系统生成新数据密钥，使用根密钥加密后返回，旧数据密钥标记为待废弃

#### Scenario: 使用新密钥重新加密数据
- **WHEN** 数据密钥轮换后需要重新加密已有数据
- **THEN** 系统使用旧数据密钥解密数据，再使用新数据密钥重新加密

### Requirement: 部署架构
系统 SHALL 支持隔离部署和多虚机/集群部署两种模式。

#### Scenario: 单机隔离部署
- **WHEN** 系统以单机模式部署
- **THEN** 密钥服务和加解密服务运行在同一进程，直接连接本地 TPM 设备

#### Scenario: 集群部署 - 密钥服务节点
- **WHEN** 系统以集群模式部署，当前节点配置为密钥服务节点
- **THEN** 该节点连接 TPM 设备，提供密钥生成、加密、解密 API，不直接执行数据加解密

#### Scenario: 集群部署 - 工作节点
- **WHEN** 系统以集群模式部署，当前节点配置为工作节点
- **THEN** 该节点不连接 TPM，通过调用密钥服务节点的 API 获取解密后的数据密钥，在本地执行数据加解密

#### Scenario: 密钥服务高可用
- **WHEN** 集群中部署多个密钥服务节点
- **THEN** 工作节点可配置多个密钥服务地址，支持故障切换，任一密钥服务节点可用即可正常工作

#### Scenario: 节点角色配置
- **WHEN** 用户通过配置文件指定节点角色（standalone / key-server / worker）
- **THEN** 系统根据角色加载对应的功能模块，未配置的功能模块不启动
